# 006 · 浏览器可玩重建（three.js）

> 从「资产出土」到「能玩」这一段的全部逆向结论。原始平台是 2005 年的 Mac / PowerPC，
> 本仓库用 three.js 在现代浏览器里重建了一个可玩的 Three.js 版本，双击根目录 `开始游戏.bat` 即可。

---

## 1. 坐标系：Unity 左手系 → three 右手系

Unity 是**左手系**（+Z 朝前），three 是**右手系**。手性转换必须**翻转一个轴**（镜像）：

```js
world.scale.z = -1;          // 正确
world.rotation.y = Math.PI;  // 错误：这是旋转不是镜像
```

用 `rotation.y = π` 会让整个场景原地转 180°——物体朝向全部反转，牌子变成背面朝人（文字左右颠倒），
场景前后也随之颠倒。材质需配合 `side: THREE.DoubleSide`。

**坑**：球（玩家）直接挂在 `scene` 上、不在 `world` 组内，因此**出生点坐标必须手动同步翻转**
（`spawn.z = -spawn.z`），否则球落在 Z 轴镜像的位置。

## 2. Mesh：strips 只能按三角带展开

Mesh 几何有两条来源：`faces`（普通三角形）与 `strips`（三角形条带）。

- 三角带的唯一正确语义：**相邻共享边 + 绕序交替**
  （`i` 偶数取 `(v[i], v[i+1], v[i+2])`，`i` 奇数取 `(v[i+1], v[i], v[i+2])`），`0xFFFF` 为段重启。
- 曾经的错误实现：把 strips 当「每 3 个顶点切一组」的三元组。结果大地形（水面 / 峡谷 / 平面）
  被拆成互不相连的三角形，俯视图呈棋盘状碎渣——大网格几乎全是 strips 型，所以全关稀碎；
  小物件走 faces 型反而正常。
- **LOD 不可混合**：多 LOD 网格的 faces/strips 必须按 MeshData 分组保存，混成一条带会整体错位。

## 3. Mesh：m_UV 的真实位置

```
m_LODData → [u32 V][V×float3] → [u32 0] ← 一个长度 0 的数组 → [u32 U][U×float2]
```

顶点数组之后**先有一个长度 0 的数组**，再是 UV。直接在顶点末尾读长度会读到 0，
于是导出的 OBJ 全部没有 vt——贴图退化成采样纹理左上角**一个像素**。
若该像素是黑的（`Water02.png` 正是 `(0,0,0)`），整片地面就会发黑。

UV 通常 `U == V`（实测 161 / 465 / 127 三个网格均如此），导出 OBJ 时面索引写成 `a/b` 复用顶点索引。

## 4. Texture2D：端序与流式存储

| 结论 | 说明 |
|---|---|
| **DXT 块端点是小端** | `c0/c1` 用 `int.from_bytes(..., 'little')`；用大端会解出满屏噪点（颜色全错但轮廓仍在）。PPC 上的 Unity 也没转端序 |
| **流式余量紧跟对象之后** | 纹理数据 = 对象内联部分 + `raw[obj.offset+size ...]`。曾经的「对象之前流洞」规则抓到的是无关数据（甚至 ASCII 文本） |
| fmt 5 = ARGB32 | 字节序 ARGB（`data[i*4+1..3]` 为 RGB）；实测星球 / 船体贴图正确 |
| fmt 12 = RGBA4444 | 低字节 RGBA，`v & 15 / v>>4 / v>>8 / v>>12` 各 4bit 乘 17 |
| mip 链 | 解码只需 mip0（`w*h*bpp` 字节），但取数时按整条链补齐更稳 |

补齐这三项后，**218 张纹理全部解出，零未支持格式**，`Water02` 满铺 UV 出蓝色水波，
桥 / 路面用上 `wood2` 木纹，`ufoSphere2` 用上 `UFO` 船体纹理。

## 6. 渲染侧

- `world.scale.z = -1` 后材质需 `DoubleSide`；阴影视锥另算（本版未做阴影）
- 纹理 `flipY = false`（Unity UV 原点在左下）+ `RepeatWrapping`（峡谷 UV 可超 1）
- 无 UV 的网格不挂贴图，改用材质 `_Color` 兜底，避免再次出现纯黑色块
- 第三人称相机需 raycast 防穿墙，否则贴墙时整屏被岩壁糊住
