# 012 - 悬空钻石排查

> 问题来源：玩家反馈「Montezuma 章第一关有一颗钻石离得很远，是 bug 还是有什么方法能吃到」。
> 结论：**不是 bug 触发不了、也不是隐藏技巧，是一颗摆在关卡几何之外的孤立钻石**——
> 脚下没有任何可站立面，弹道也够不到。全库 262 颗钻石里只有 2 颗属于这种情况。

## 一、定位

「Montezuma 章第一关」= **Quagmire**（全局第 14 关，场景 `level20`），关卡表里声明 4 颗钻石
（见 [`011-各关钻石统计.md`](011-各关钻石统计.md)）。

4 颗 `StarPickup` 的世界坐标（Transform 沿父链合成，父链 `Level Pivot/Holder` 为单位变换）：

| # | 世界坐标 | 支撑面 | 判定 |
|---|---|---|---|
| 1 | (-53.74, -0.28, -31.03) | 有 | 关卡内 |
| 2 | **(19.12, 0.88, 5.99)** | **无** | **悬空** |
| 3 | (-50.84, -0.28, -35.36) | 有 | 关卡内 |
| 4 | (-44.41, 0.42, -42.96) | 有 | 关卡内 |

关卡主体几何（`rim` 地面 + 各 `polySurface`）的世界包围盒：

```
X[-81.4, -16.2]   Y[-2.0, 0.9]   Z[-56.7, 8.5]
```

第 2 颗在 **X = +19.12**，比地面最东边（X = -16.2）还远 **35.3 单位**。
它不是「远一点的平台」——该 XZ 位置上，全关 52 个网格没有任何一个覆盖，
连 `LevelInfo.levelRadius = 32.29` 也被突破（它距关卡中心 74.5，是半径的 2.3 倍）。

## 二、为什么吃不到：弹道算术

物理参数取自 `sharedassets.assets` 的 `BallController`（pid=1906）实测：

| 参数 | 值 |
|---|---|
| `maxSpeed` | 16.0（全局速度钳制，任何时刻初速上限都是它） |
| `gravityInAir` | 15.0 |
| `jumpForceSticky` / `jumpForceHard` | 7.2 / 5.7 |
| 球半径 | 0.3 |

- **理论最大射程**：`R = v²/g = 16² / 15 = 17.1` 单位（还要假设理想的 45° 出手角）。
  实际跳跃是沿接触法线向上（`jumpUpAngle` 20°），黏球跳回原高度约 0.96 s，
  水平只前进 **≈15.4 单位**。缺口是 **35.3 单位**，是极限射程的两倍多。
- 即使假设能飞过去，落点也是**虚空**——那边没有任何碰撞面，球会直接掉出去。

关卡倾斜（`LevelTilter`）不改变这个结论：把整关旋转只改变地面朝向，
球离开地面后仍在世界重力下走抛物线，初速一样被钳在 16。

## 三、全库对照：只有 2 颗

用工具扫全部 61 关 262 颗钻石（判据：钻石 XZ 位置是否落在某个
`MeshFilter` / `MeshCollider` 网格的世界包围盒内，且排除钻石自身子树）：

| 场景 | 关卡 | 坐标 |
|---|---|---|
| `level20` | Montezuma #1 · Quagmire | (19.12, 0.88, 5.99) |
| `level55` | Aztec Spacerace #3 · Faster, Faster | (-79.11, -8.29, -53.01) |

**合计 2 颗 / 262 颗（0.76%）**。其余 260 颗下方都有真实几何。

## 四、性质与影响

- 这颗钻石的 `StarPickup` 组件字段与同关另外三颗**完全一致**
  （`m_Speed=(0,1,0)` 上下浮动、`m_KillDelay=2.0`），子物体 `diamond` 带
  Renderer + MeshFilter + 反射 flare + 点光源，所以**远处看得见**，
  容易被误认为「有隐藏路线」。
- 没有任何机关能送过去：该关 MonoBehaviour 只有
  `LevelTilter` / `LevelInfo` / `QualityMaterialSwitcher` / `ReflectionRenderTexture`
  / 4×`StarPickup` / `GoalTrigger`，**没有**弹射（`CatapultAction`）、传送、
  移动平台（`PlatformMover`）之类的载体，全关也没有一处跳台朝东。
- 影响面：星星只用于 **10 星换 1 命**（`kStarsForOneLive = 10`），
  不参与关卡解锁（解锁看 `LastUnlockedChapter`）。所以这颗拿不到，
  最多少 1 星、少一次换命机会，**不挡进度**。
- 成因判断：关卡编辑遗留物。同一关卡的地面板块或整体曾移动/裁切过，
  钻石没跟着挪；`level55` 那颗同理（同一份关卡工程里复用的放置习惯）。

## 五、机关排查（二次核验：本关一个能「送人过去」的东西都没有）

把本关 95 个节点、9 个 MonoBehaviour 与全游戏 84 类脚本逐一对照：

| 可能的「运送型」机关 | 全游戏实例 | 出现场景 | 本关（level20） |
|---|---|---|---|
| `CatapultAction`（弹射器） | 56 | 8 | **无** |
| `PlatformMover`（移动平台） | 11 | 4 | **无** |
| `ActivateTrigger`（触发式机关） | 222 | 19 | **无** |
| `DelayedTrigger`（延时触发） | 4 | 3 | **无** |
| `FalloutCollider` | 8 | 2 | **无** |
| `AutoHeightRespawn` | 18 | 18 | **无** |

本关全部脚本只有 6 类：`LevelTilter`、`LevelInfo`、`QualityMaterialSwitcher`、
`ReflectionRenderTexture`、4×`StarPickup`、`GoalTrigger` —— 全是视角/材质/收集/终点，**没有位移载体**。

另外逐项排查：

- **动画**：本关带 `Animation` 的节点只有 3 座图腾 `kabala1/2/3` 和 4 颗钻石；
  钻石共用 `pickupanim`（上下浮动），`montezuma_levelRim`（地面）虽然挂了 Animation 组件
  但 **clip 列表为空**，地面完全静止。没有任何「平台摆过去」的动画。
- **关卡倾斜**：`LevelTilter` 组件无自定义字段（全用默认），倾斜只改变滚动方向，
  不产生位移，也不改变初速上限（仍钳在 16）。
- **层级**：那颗钻石与另外三颗同为 `Level Pivot/Holder/star pickup`，
  没有独立的移动父节点可利用。
- **落点**：即使有空路过去，钻石所在的 X 区间没有任何碰撞面，只会掉出关卡
  （本关连 `FalloutCollider` / `AutoHeightRespawn` 都没配）。

结论：**没有任何机关**。这是纯静态摆放错误，不是「需要某个技巧触发的谜题」。

## 六、复现

```bash
python tools/level_diamond_support.py            # 全 61 关扫描
python tools/level_diamond_support.py level20    # 单关逐颗明细
```

输出末尾会打印判据阈值：`maxSpeed²/g = 16.0²/15.0 = 17.1 单位`。

## 七、若想让它「能吃到」

纯属可选，不影响原版存档：

1. **挪进关卡内**：把 `level20` 里该 `star pickup` 的 `m_LocalPosition`
   改到地面范围内（例如与第 3 颗同区），一处 12 字节浮点即可。
2. **放低 + 拉近**：若要保留「远眺感」，把它放在 X≈-18 的地面边缘上方即可进入可达射程。

两种改法都只需要改关卡文件，`sharedassets.assets` 不动。
